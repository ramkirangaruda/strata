Incident report — commit a2447a7

The bug that broke every Open()

Not a hypothetical. This shipped, was caught, and is fixed in this repo's history — strata.Open() failed on the first call, every time, on every Windows machine.


    

  






  

    

      
What happened

      
Symptom → root cause → fix → tradeoff

    

    

      

        
01 — Symptom

        
strata.Open() failed before doing anything else

        
100% reproduction on Windows. Not a rare race, not a corrupted-file edge case — the very first call to strata.Open(), on an empty directory, returned an error. Nothing built on top of the engine could even start.

      

      

        
02 — Root cause

        
Directory fsync doesn't exist on Windows

        
After writing or renaming a file, strata calls fsync on its directory too — a standard POSIX trick (see docs/DESIGN.md §4) so a crash can't leave a durable file with no durable directory entry pointing at it. Windows has no equivalent: FlushFileBuffers on a directory handle returns ACCESS_DENIED, full stop.

      

      

        
03 — The fix

        
A 16-line, purely additive patch

        
Skip the directory fsync when runtime.GOOS == "windows". No change to behavior on Linux or macOS, where the guarantee still holds exactly as documented.

      

      

        
04 — The tradeoff, on the record

        
A documented gap, not a hidden one

        
On Windows, a crash at exactly the wrong instant could in principle leave a durable file with no durable directory entry. That's a real gap against the POSIX guarantee in DESIGN.md §4 — written into the source comment rather than quietly ignored.
